- 수집원 수는 `sources.json` 카운트를 build_data가 주입해도 되고, 첫 버전은 하드코딩도 무방.

### 0-2. 귀속 표기 통일 (Carbon Brief 발췌 공식)
카드·상세의 요약 근처에 publisher가 이미 있는지 확인 후, 없다면 요약 블록에

수집하지 말 것). 직접 인용문이 요약에 들어갈 때 따옴표+출처는 이미 summary 사실성 제약이
커버 — 규칙 추가 불필요.

## Phase 1 — 반나절, 프롬프트+노출 (LLM 호출 증가 0)

### 1-1. Pretitling 규칙 (Techmeme)
`news_bot.py` CURATION_SYSTEM_PROMPT의 title_kr 항목(현행: "한국어 제목 30~60자, 번역")에 추가:

```
- title_kr 은 번역이 아니라 요약 헤드라인이다. 클릭 없이 요점을 알 수 있게 쓴다.
  · 주체 기관·기업명을 반드시 포함 (예: "정부가" (X) → "산업통상부가" (O))
  · 원문에 있는 핵심 수치 1개(용량·금액·기수·시한)를 제목에 보존
  · 능동 동사로 끝맺음 — "~에 대한 논의" (X) → "~를 승인했다" (O)
  · 원 기사 제목이 리드를 묻거나 주체를 생략했으면 본문 기준으로 재작성
```

- 배포 전 게이트(CLAUDE.md 규칙): **샘플 1배치 시각 검증 후 진행.** 로컬 키로 10건
  돌려서 제목 품질 눈으로 확인 → 그다음 push.
- 위험: 프롬프트 변경은 전 카드에 영향. 429와 무관(호출 수 동일)이나 출력 길이 미세 증가.

### 1-2. open_question → "관찰 포인트" 노출 (Axios What to watch)
- 상세 화면 "Nuclens 해석" 블록 아래에 `관찰 포인트:` 라벨로 open_question 렌더(null이면 미렌더 —
  기존 원칙 "예외만 표시한다"와 일치).
- THIS WEEK 후보 선별 신호로도 사용 가능: open_question이 있는 must_read는 추적 가치가
  높다는 뜻 — ranking_config 가중치가 아니라 **웹 표시만** 먼저 (랭킹 개입은 레이블 축적 후).
- 파일: `web/build_data.py` (필드 통과 여부 확인) + `web/public/app.js` (렌더 1블록).
- `node --check web/public/app.js` 필수 (2026-08-01 실사고).

### 1-3. 카드 라벨 표기 정리 (Semafor+Axios 교집합)
현행 카드가 이미 사실/해석을 분리하고 있으므로 **라벨 문구만 통일**:
- `summary` → 라벨 없음(카드 본문 = 사실. Axios "라벨 남발 금지")
- `why_important` → **왜 중요** (AI 해석 배지 유지)
- `implication` → **시사점** (AI 해석 배지 유지)
- 이 세 이름은 □(사실)–○(왜 중요)–※(시사점) 개조식 위계와 1:1 — 보고서 복사 기능의
  출력 템플릿도 같은 순서로 맞춘다 (`web/build_data.py`의 보고서 팩 복사 부분).

## v2 수정 — 2026-08-16 외부 리뷰(ChatGPT) 교차검토 반영

외부 리뷰 전문은 대화 기록. 코드베이스 실태와 대조한 판정과 수정만 기록한다.

### 수용 — 계획 변경

1. **서비스 정의 = "원자력 정책 상황판(트래커)"** — 기존 브랜드 결정(디스크립터
   "원자력 정책·산업 이슈 트래커", web/brand/)과 이미 일치. 이 정의를 모든 화면 판단의
   기준으로 명문화. 참조 가중치도 리뷰 제안대로: **Techmeme·Carbon Brief 코어 /
   Axios·뉴닉 표현 / Heatmap 장기 방향 / Semafor 편집 원칙 / 1440 철학만**.

2. **3층 톤 분리 강화 — TODAY 웹 카드에서 `implication`(시사점) 표시 제거**:
   - `TODAY = 사실(summary) + 왜 중요(why_important) + 관찰 포인트(open_question) + 출처 줄`
   - `THIS WEEK = 변화 + 맥락 + 해석` / `보고서 = 한수원 관점 시사점`
   - 근거: "시사점은 매일 만들어낼 정보가 아니다" — 현행 프롬프트가 정확히 이 함정에
     빠져 있음: **"implication: must_read·nice_to_know 는 반드시 작성 — 빈 문자열·null 로
     두지 말 것"(news_bot.py) = Axios 비판의 빈칸 강제 그 자체.**
   - 실행: ①프롬프트에서 "반드시 작성" 강제를 "근거가 원문에 있을 때만, 없으면 null"로
     완화 ②웹 TODAY 카드에서 implication 미렌더(보고서 복사·THIS WEEK에는 유지).
   - **⚠️ 필드 삭제 금지**: 텔레그램 브리핑이 소비 중 — daily_brief.py:257·383(why
     fallback)·453(kr_takeaway). null 허용 시 텔레그램 라인 공백 처리 확인 필수.

3. **TODAY 상단 구조 = "오늘 알아야 할 5가지 / More Signals / River"**:
   현행 홈 이원 구조('지금 달라진 이슈' 최대 5 / '오늘 확인된 이슈')가 이미 80% —
   섹션명 재정의 + 하단에 "전체 수집 보기(River)" 링크(아카이브 탭 재사용, 신규 페이지
   불필요)로 완성.

4. **출처 표기 = 라이트 배지 + 펼침 번들**: 카드 전면엔 `Reuters 외 N · 관련 M건`
   수준만, 상세 펼침에서 전체 source bundle(이미 타임라인으로 존재). 단 **N≥3일 때만
   배지 표시** — 이슈의 84%가 단일 출처(2026-08-01 실측)라 전 카드에 달면 신호가 죽는다
   ("예외만 표시" 원칙과 리뷰 제안의 절충). Phase 0-2의 "요약 문두 귀속"은 이 방식으로 대체.

5. **"중립" 목표어 교체**: 중립성 → **추적 가능성 + 사실/해석 분리 + 불확실성 표시**.
   verification 4단계가 이미 불확실성 표시를 담당. 쟁점 이슈(찬반 구도)에 한해
   **주장 귀속 블록**(주체별 "누가–무엇을 주장–근거 원문") 추가 — 전 이슈 적용 금지,
   상세 화면 한정, LLM 배치 판정으로 쟁점 여부 플래그.

6. **라운드 2 조사 예약**: 미디어가 아닌 **인텔리전스 제품** — Bloomberg Terminal,
