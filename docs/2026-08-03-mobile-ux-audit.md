## 고친 방식에서 재사용할 만한 것

- **가로 스크롤 스트립은 잘림을 숨기는 장치다.** 항목마다 `<span>` 을 주고
  구분자를 `::before` 로 그리면 좁은 화면에서 낱말이 아니라 **항목 단위**로
  접힌다. 실측 714px 1줄 → 366px 2줄(54px), 정보 손실 0.
- **`<details>` 를 바텀시트 모양으로 만들면 바텀시트의 계약도 져야 한다.**
  스크림은 `::before` 라 클릭 `target` 이 `details` 자신으로 잡힌다 —
  `event.target === drawer` 로 스크림 탭을 구분할 수 있다.
- **한 컴포넌트를 데스크톱 사이드바 / 모바일 시트로 겸용**할 때는 CSS 로
  `open` 을 흉내내지 말고 `matchMedia` 로 `open` 속성을 관리할 것. UA 가
  `details` 내용 표시를 `display` 로만 다루지 않아 CSS 오버라이드가 깨진다.
- **바텀시트가 결과를 덮으면 적용 결과를 시트 안에 다시 써야 한다.**
  `#filterSheetCount` · `#archiveSheetCount` 가 그 역할.
- **`.section-count { order: -1 }` 은 부모가 grid 로 바뀌는 순간 의미가 뒤집힌다.**
  개수가 제목 위로 올라갔다. 정렬 규칙은 그것이 사는 컨테이너로 스코프할 것.
- **12.5px 하한 테스트는 '미만'만 잡는다.** 올리는 방향은 안전하다 — 액션
  라벨(저장·공유·원문)은 13.5px 로 올렸다.

## 남은 것

- `.issue-summary` 는 여전히 3줄 클램프다. 전문은 상세에서 보지만 카드에서
  '더 보기' 를 원하는지는 사용자 판단.
- 발간물 기관 필터 칩이 320px 에서 4줄(약 170px)을 쓴다. 칩 수가 늘면 스크롤
  가능한 한 줄로 바꾸는 편이 낫다.
- 검색 결과가 없을 때의 빈 상태는 있으나, **검색 실패 원인별 안내**(오타 추정
  등)는 없다.
- `role="status"` 를 시트 안에 둔 탓에 시트를 열 때 개수가 한 번 더 낭독될 수
  있다. 실기기 스크린리더(TalkBack/VoiceOver) 확인은 못 했다 — 헤드리스 한계.
