## 0. 이 시현회가 말하는 한 문장

> **AI가 일을 대신하는 게 아니라, 매번 다시 하던 판단을 한 번 적어두는 것입니다.**
> 교정 패턴이든, 출처의 함정이든, 뉴스 선별 기준이든 — 한 번 적어두면 그다음부터는 공짜입니다.

오프닝과 클로징에 각각 한 번씩, 같은 문장으로. 세 사례 모두 이 구조의 실례다.

**말하지 말 것**: "AI가 알아서 해줍니다", "생산성 N배", "혁신". 실·처 청중은 이런 말을 3년째 듣고 있다.
**말할 것**: 어떤 단계가 왜 사라졌는지. 숫자는 줄어든 왕복 횟수로.

## 2. 오프닝 (1분)

> "오늘 세 가지 업무를 가져왔습니다. 국회 질의 대응, 정기 참고자료 갱신, 아침 뉴스 정리. 전부 제가 실제로 하는 일이고, 전부 AI를 붙여본 일입니다.
> 각각에 대해 **기존에 며칠이 걸렸고 누가 참여했는지**, 그리고 **어떤 단계가 사라졌는지**만 보여드리겠습니다.
> 결론부터 말씀드리면 — AI가 일을 대신하는 게 아닙니다. 매번 다시 하던 판단을 한 번 적어두는 것입니다."

## 3. 사례 ① 국회 질의 대응 자료

### Before

| | |
|---|---|
| 단계 | 질의 접수 → 담당 배정 → 자료 수집 → 초안 작성 → **차장 교정** → **부장 교정** → 취합·제출 |
| 소요 | 건당 반나절~1일, 교정 왕복 **2~3회** |
| 참여 | 담당자 + 차장 + 부장 (3명) |

### After

| | |
|---|---|
| 단계 | 질의 접수 → 담당 배정 → 자료 수집 → **초안(= 교정 후 상태)** → 부장 확인 → 취합·제출 |
| 소요 | 교정 왕복 **1회 이하** |
| 참여 | 담당자 + 부장 (차장은 확인만) |

### 스킵된 단계: **1차 교정 왕복**

**핵심 메시지** — "AI가 글을 잘 써서"가 아니다:

> "교정 지적을 모아보니 **매번 같은 것**이었습니다. (주요질의)/(장관답변) 라벨 누락, 수치가 헐거움, 주술 호응이 안 맞음, 질의 취지를 안 받음.
> 그래서 그 패턴을 규칙으로 적어뒀습니다. 이제 초안이 처음부터 그 상태로 나옵니다.
> **차장님 교정을 AI가 대신하는 게 아니라, 차장님이 같은 지적을 두 번 안 하시게 된 겁니다.**"

### 화면에 띄울 실물

- 교정사례집 (기노위 2026-08-12) — 지적 → 규칙 변환 과정
- 지적 유형 상위 4개와 각각의 발생 빈도

## 4. 사례 ② 정기 참고자료 갱신 (원자력 참고자료 1.1~1.6, GDP Top20 원전 현황)

### Before

| | |
|---|---|
| 단계 | 출처 사이트 **재탐색** → 최신 판본 확인 → 수치 전사 → 표 갱신 → 검증 |
| 소요 | 표 1개당 반나절, 6개면 **며칠** |
| 참여 | 담당자 1명 (시간이 통째로 감) |

### After

| | |
|---|---|
| 단계 | **대조** → 표 갱신 → 검증 |
| 소요 | 표 1개당 1~2시간 |
| 참여 | 동일 (사람이 수치를 확인하는 건 그대로 둔다) |
| 반복 비용 | 함정 재발견 **0** |

### 스킵된 단계: **원문 경로 재탐색 + 함정 재발견**

**핵심 메시지**:

> "이 작업에서 진짜 시간을 먹는 건 수치 옮겨적기가 아니라, **작년에 이미 겪은 함정을 올해 또 겪는 것**이었습니다.
> IEA WEO는 판본마다 시나리오 기호가 바뀝니다. IAEA PRIS는 사이트가 개편됐습니다. 일본은 기수 집계가 자료마다 다릅니다.
> 이런 걸 아홉 개 적어뒀더니, 갱신이 **'찾기'에서 '대조'로** 줄었습니다."

**주의**: 여기서 "사람 검증은 그대로 남긴다"를 반드시 말한다 — 뒤의 우려 섹션 3번과 연결되는 복선.

## 5. 사례 ③ 아침 뉴스 → 동향 파악 → 보고 (**라이브 3분**)

### Before

| | |
|---|---|
| 단계 | 스크랩 읽기 → 중요한 것 판별 → **배경·경과 찾기** → 보고 필요 판단 → 골격 작성 |
| 소요 | **매일** 30분~1시간 + 보고 건당 반나절 |
| 참여 | 담당자 (매일) |
| 사각 | 해외·공식기관 원문은 스크랩에 안 들어옴 |

### After

| | |
|---|---|
| 단계 | 아침 브리핑 수신 → 이슈 클릭 → **개조식 초안 복사** |
| 소요 | 매일 5분 + 보고 건당 1~2시간 |
| 참여 | 동일 |
| 사각 | 수집원 46곳이 자동으로 채움 |

### 스킵된 단계: **읽고 고르기 + 배경 찾기**

### 라이브 동선 (이 순서 외 클릭 금지)

1. **폰 화면 또는 캡처** — 아침 텔레그램 카드. "매일 아침, 출근길에 이미 와 있습니다"
   → ⚠️ 정확한 시각은 **9/15에 실측값으로 확정**한다. 설계상 **08:00~08:25** 도착 (카톡 조간 07:15이 크롤에 반영된 직후 발송되도록 크롤 완료에 묶어놨다). 확정 전까지 구체 시각을 말하지 않는다
2. **오늘 탭** — 이슈 카드. 중요도·검증 배지·AI 표시를 짚는다.
   → "AI가 쓴 문장에는 전부 AI 배지가 붙습니다. **사실과 해석을 섞지 않는 게 설계 원칙**입니다"
3. **이슈 상세** — ⚠️ **데스크톱은 2클릭이다.** 카드를 누르면 우측에 요약 rail이 열리고, 거기서 **"전체 상세"**를 한 번 더 눌러야 타임라인·스토리·복사 버튼이 나온다. 리허설에서 반드시 손에 익힐 것
   → 검증(공식 원문·독립 출처 수), 사건 타임라인. 진행 중 사안이면 **스토리** 열기
   → 스토리 멘트: "**몇 주에서 한 달 넘게 이어지는 경과**를 한 줄기로 묶습니다" (※ "60일"이라고 말하지 말 것 — 실측 최대 51일, 아카이브 자체가 57일치라 구조적으로 불가능)
4. **⭐ 보고서용 복사** — 개조식 초안을 복사 → 보고서 골격에 붙이기
   → "**기사 읽기에서 보고서 초안까지의 거리를 줄이는 것**이 목적입니다"
5. **흐름 탭** — 주간 판세·이어지는 사안·일정 캘린더 (빠르게 훑기)

**4번이 킬러다.** 여기에 3분 중 1.5분을 쓴다. 3·5번은 빠르게.

> **데모 이슈는 미리 고정한다 (§12 참조).** 임의 클릭 금지 — 스토리 서사가 있는 이슈는 71개 중 9개뿐이라, 아무거나 열면 스토리가 비어 보인다. 9/15까지 PRIMARY·BACKUP 2건을 정해 직링크를 여기에 적어둘 것.
>
> PRIMARY: `(9/15 확정)`  /  BACKUP: `(9/15 확정)`

## 6. 활용법 (1분) — 여기가 이 시현회의 승부처

> "**설치할 게 없습니다. 주소 하나입니다.**
> nuclens.pages.dev 여시고 → 이슈 클릭 → '보고서용 복사'. 그게 전부입니다. 로그인도 없습니다.
> 지금 폰으로 QR 찍어보십시오. 30초면 됩니다."

**QR 코드를 슬라이드에 크게.** 그 자리에서 청중이 자기 폰으로 연다.

- 설치 0을 **말이 아니라 실물로 증명**한다
- **라이브 데모 백업이 된다** — 발표자 화면이 죽어도 청중 폰에서는 살아 있다
- 회사 PC에서 텔레그램이 막혀 있어도 개인 폰 구독은 뚫린다

이어서:

> "①번 국회 질의 교정과 ②번 참고자료 갱신은 **같은 원리로 됩니다. 다만 아직은 제가 돌립니다.**
> 반복되는 일이 있으시면 말씀해 주십시오. 그게 오늘 제가 드리는 제안입니다."

→ **오늘 쓸 수 있는 것 1개 + 만들어 드릴 수 있는 것 예시 2개 + 접수창구.**

## 7. 우려하는 점 (2분) — 장식이 아니라 신뢰를 만드는 섹션

**말투 주의**: 겸손 떠는 톤이 아니라, 이미 설계에 반영했다는 톤으로.

1. **환각은 없어지지 않습니다.**
   그래서 nuclens는 사실(기사 인용)과 AI 해석을 **분리해서** 표시하고, 해석에는 전부 AI 배지를 붙였습니다. 숫자와 인용은 원문 링크로 반드시 대조하셔야 합니다. **"AI가 썼으니 맞겠지"가 가장 위험합니다.**

2. **보안 경계가 있습니다.**
   오늘 보여드린 것은 전부 **공개 자료** 기반입니다. 내부 문서나 미공개 자료를 외부 AI에 넣는 것은 완전히 별개 문제이고, 승인된 경로 안에서만 해야 합니다. 이 도구는 그 선을 넘지 않도록 만들었습니다.

3. **검토 근육이 빠집니다.**
   초안이 좋을수록 검토를 안 하게 됩니다. ②번에서 사람의 수치 대조를 일부러 남겨둔 이유가 이것입니다. **판단은 여전히 사람이 합니다.**

4. **지금은 개인 의존입니다.**
   현재 개인 계정과 개인 인프라 위에서 돕니다. 부서 자산으로 쓰시려면 계정·인프라 이관이 선행되어야 하고, 이건 별도로 보고드리겠습니다.

## 9. 예상 질문 답변

- **"틀린 정보가 나가면?"** → 사실과 AI 해석을 분리 표시하고 해석엔 전부 배지. 검증 배지는 공식 원문·복수 출처 확인 기반. 원문 링크가 항상 붙어 검증 가능. (경영진 단계까지 재현율·사실성 측정 숫자 추가 예정)
- **"운영은 누가?"** → 현재 자동화 파이프라인 + 개발자 1인 관리. 공식화 시 계정·인프라 이관 방안 별도 보고. **솔직하게 — 숨기면 나중에 더 아프다.**
- **"비용은?"** → 현재 0원(무료 티어). 사용량 증가 시 월 수만 원 수준 예상 — 정확 시나리오는 경영진 보고에 포함.
- **"차장님 것과는?"** → 같은 뿌리에서 상호 검증하며 발전 중 — 상대 개선점을 5차례 상호 반영. 경쟁이 아니라 이중화·교차검증 구조.
- **"신문스크랩이랑 뭐가 달라?"** → 대체가 아니라 보완. 스크랩방의 선별을 시드로 활용하고 있고(⚠️ 9/14 시드 파이프라인 판정 후 현재형/과거형 확정), 해외·공식기관 원문처럼 스크랩이 못 닿는 영역을 자동으로 채움.
- **"우리 부서 업무에 어떻게 써?"** → 사례 ③이 답. + 아침 브리핑 구독(텔레그램).
- **"내 초안도 교정해주나?"** → 아직 아닙니다. 사이트는 현재 미리 만들어둔 것만 보여주는 구조라, 입력받아 처리하려면 별도 설계가 필요합니다. **다음 단계로 보고 있습니다.** (§11 B1)
- **"회사 PC에서 되나?"** → 브라우저만 있으면 됩니다. 설치가 필요 없어서 별도 승인 절차도 없습니다.

## 11. 부록 — nuclens 제품 방향 (시현 이후)

### 관점 전환

nuclens는 "뉴스 사이트"가 아니라 **설치 없는 업무 산출물 배포 경로**다. 이 관점에서 로드맵은 *기능*이 아니라 **입력이 어디서 오는가**로 갈린다.

구조적 사실: nuclens는 **prebuild-and-serve**다. 야간 파이프라인이 정적 JSON을 만들고 Cloudflare Pages가 서빙한다. 런타임 LLM 호출은 없다.

### Tier A — 입력이 미리 정해진 것 (현 구조 그대로, 싸다)

**A1. 예상 국회 질의 + 답변 골격** ★ 최우선

- 국감·상임위 질의는 뉴스에서 역산 가능하다. must_read 이슈에 "이것이 질의로 나온다면"을 붙여 prebuild
- 교정 패턴(개조식 규칙·QnA 문체)은 **이미 박제돼 있다** — 생성층이 있다
- 사례 ①을 self-service로 전환하는 첫 걸음. 입력이 사용자 텍스트가 아니라 **이슈**라서 런타임이 필요 없다

**A2. 참고자료 자동 갱신 탭**

- PRIS는 JSON API가 있다. GDP Top20·참고자료 1.1~1.6을 파이프라인이 갱신
- 함정 9개가 이미 문서화돼 있어 규칙으로 변환 가능
- 월 1회 갱신이면 LLM 거의 불필요(API + 규칙) → 쿼터 부담 ~0
- 사례 ②를 self-service로 전환

**A3. 기존 강화** — report_pick 주제별 확대, 정책의제 트랙 확장

### Tier B — 입력이 사용자 텍스트인 것 (런타임 필요, 비싸다)

**B1. 초안 붙여넣기 → 개조식 교정** ★ 시현 이후 1순위

- 문제: 공개 사이트 + LLM = API 키 노출면 + 쿼터 개방 + 남용
- **해법이 이미 repo 안에 있다**: `functions/admin/_middleware.js` — ADMIN_PASSWORD + HMAC 서명 세션 쿠키. 이 게이트를 `/tools` 경로에 재사용하면 *익명 공개 LLM 엔드포인트*(위험)가 *비번 아는 사람만 쓰는 사내 도구*(관리 가능)로 바뀐다
- 쿼터는 `ADMIN_KV`(이미 바인딩됨)로 1인 1일 N회 제한
- 이게 실·처 직원이 **자기 업무에** 쓰는 첫 기능이 된다
- 파생 효과: "교정 품질을 어떻게 측정하나"가 바로 따라온다 → **Evals 트랙의 실사용 근거**

### Tier C — 안 하는 것 (근거 포함)

- **회사 내부 문서 업로드**: 보안 경계 밖. 승인 없이 절대 안 함
- **익명 공개 LLM 엔드포인트**: 무료 티어 쿼터로 불가, 남용 방어 비용이 기능값을 초과

### Tier 0 — 선결 조건

**운영 이관.** 개인 계정·개인 인프라 의존은 부서 자산화의 선결 조건이고, A/B 어느 것보다 먼저다. 경영진 보고의 핵심 안건.

### 순서

```
Tier 0 (이관 협의)  →  A1 (예상 질의)  →  B1 (교정 도구)  →  A2 (참고자료)
```

A1이 B1보다 먼저인 이유: 런타임 인프라 없이 사례 ①의 가치를 절반 증명할 수 있고, 그 반응을 보고 B1 투자를 결정할 수 있다.
