# 카드 사실 줄 개선 계획 — "달라진 것"을 정직하게

> 2026-08-17. 계기: 지니가 화면을 보고 던진 두 질문 —
> "아직도 몇 개는 잘려 있다", "이건 실제로 달라진 걸 분석한 거냐 기사 요약이냐".
> 앞선 작업: `2026-08-16-supersample-apply-plan.md`(v3), 커밋 `1820551`·`064d428`.

## 진단 (전부 실측, 2026-08-16 빌드 / 이슈 271건 기준)

**① "달라진 것"은 델타 분석이 아니다.** `latest_change_line()`은 이전 기사의
`summary`(48자 압축)와 최신 기사의 `summary`(112자 압축)를 `→`로 잇는다. LLM이
두 시점을 비교해 쓴 문장이 아니다. 안전장치는 하나 — 두 요약이 재진술이면 아예
만들지 않는다(2026-08-09 감사 산물).

**② 커밋 `064d428`이 유일한 정보를 버렸다.** 카드에 올린 `card_change`(화살표
뒤)와 `summary`의 자카드 유사도가 **중앙값 1.00**, 69%가 완전히 동일하다. 즉
"달라진 것" 라벨을 달고 최신 기사 요약을 다시 보여주고 있다. 코드 주석이 이미
경고한 것을 정면으로 어겼다 — *"뒤쪽은 카드의 제목·요약이 이미 말하고 있어
잘려도 복구되지만, 앞쪽은 화면 어디에도 없는 유일한 정보"*.

**③ 남은 말줄임은 CSS가 아니라 데이터에서 난다.** 그리고 **전부 앞쪽에서 난다.**

| 항목 | 값 |
|---|---|
| 변화 문장 보유 | 36/271건 (13%) — 화살표 25건 + 직전상태만 11건 |
| 화살표 25건의 말줄임 위치 | **앞쪽 17건 / 뒤쪽 0건** |
| `change_display` 길이 | 중앙값 139자 (예산 `CHANGE_LINE_LIMIT=140`에 딱 붙음) |
| 앞쪽(직전 상태) 실제 길이 | 중앙값 53자 · 최대 78자 |
| `summary` 말줄임 | **0%** (271건 전부 완결) |

140자 예산이 앞쪽을 `_clip()`으로 깎는다. 앞뒤를 온전히 담으려면 약 168자가
필요한데, 카드 3줄은 약 96자다 — **A → B 전문을 카드에 넣겠다는 발상 자체가
예산상 불가능**하다. 상세·근거 패널은 clamp가 없으니 거기가 그 문장의 자리다.

## 방향

카드는 **완결된 짧은 사실 하나**, 전문은 상세로. 라벨은 내용과 일치시킨다.

### Step A — 라벨 정직화 + 카드 필드 재배치 (LLM 0, 반나절)

- 카드 사실 줄 = **`summary`**, 라벨 **"무슨 일"**. 근거: 271건 전부 보유,
  말줄임 0%, 중앙값 73자로 3줄에 완결. (지금은 13%만 채워지는 `change_display`가
  이 자리를 차지하고 87%는 폴백으로 돌던 구조)
- 추적 이슈(13%)에 한해 **"직전까지"** 한 줄 추가 = 화살표 **앞**쪽. 화면 어디에도
  없는 유일한 정보이자, 카드가 "추적 중"임을 말하는 값.
- **`card_change` 폐기** — `summary`와 중복(자카드 1.00). 커밋 `064d428`의 이
  부분을 되돌린다. `line-clamp: 3`과 render_smoke 높이 가드는 유지(summary 73자가
  3줄을 필요로 하므로 그대로 옳다).
- 상세·근거 패널은 `change_display`(A → B) 전문을 계속 쓴다 — 변경 없음.
- **게이트**: 칸이 최대 3개(무슨 일 / 직전까지 / 왜 중요한가)가 되므로 220px 밀도
  계약을 실측으로 재확인. 초과하면 "직전까지"를 2줄로 낮춘다.

### Step B — 앞쪽 말줄임 제거 (LLM 0, 1~2시간)

- `CHANGE_LINE_LIMIT = 140`은 카드 한 줄 시절 상수다. 카드가 A → B를 더 이상
  쓰지 않으므로 이 예산의 소비자는 상세·RSS뿐 — **180으로 올린다**(앞 78 최대 +
  구분자 + 뒤 112 = 193의 여유선, 실측 후 확정).
- `_clip` 발동은 예외 경로로 남기되, 발동 건수를 `field_fill` 계기판에 싣는다
  ("변화 문장 말줄임 N건") — 다시 늘면 로그에서 보이게.
- 검증: 재빌드 후 앞쪽 말줄임 17건 → 0건.

### Step C — 진짜 델타 (조건부, 착수 전 재판정)

"무엇이 달라졌나"를 한 문장으로 쓰려면 두 시점을 비교하는 LLM 판단이 필요하다.
이건 계획이 금지한 **신규 상시 호출**이므로 기본은 보류. 다만 값이 크므로 조건을
명시해 둔다.

- 규모: 추적 이슈는 하루 36건 수준 → 배치 1~2회로 충분(신규 호출 계열 중 가장 쌈).
- **착수 조건**: ①Step A/B 배포 후 2주간 `field_fill` 계기판에서 추적 이슈 비율이
  유지될 것 ②쿼터 여유가 429 없이 2주 연속 확인될 것.
- 설계 원칙(착수 시): `issue_review.py` 패턴 복제 — 캐시 + dirty 플래그 + 실패 시
  기존 값 유지 + 근거 hash 저장. 판정 못 하면 **빈칸으로 두고 Step A의 "직전까지"로
  물러난다**(빈칸 강제 금지 원칙).

## 하지 않는 것

- 카드에 A → B 전문 넣기 — 예산상 불가능(168자 vs 3줄 96자)
- `summary`를 늘려 변화까지 담기 — 프롬프트의 100자 상한은 목록 한 줄 계약이라 유지
- 병합 임계·클러스터링 손대기 — 이 작업과 무관한 층(가드레일 유지)
- 디자인 변경 — 별도 트랙
